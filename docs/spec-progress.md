## 已確認的方向
- 範本由 Claude 起草（`docs/README.md`、`01`、`02`、`adr/0000`、`interfaces/IF-000`）
- 規格描述現況（as-is），以 `main`（`3147b48`）為準；企劃與規格衝突時以 code 與規格為準
- 玩法只寫能力層級；細節與數值引用 `docs/遊戲設計企劃.md`
- 品質需求用 QS 表達，QS 直接寫來源 STK（README 已改）

## 已決定的範圍事項
- 舊存檔：只保證已存在的相容程式（CON-013：SYS-002、004、036、112），之後不寫新搬移
- 防作弊三條都是 Should、未實作：SYS-080（驗證意圖）、081（玩家資料主機為準）、082（只接受主機發出的世界變更）；實作時不能犧牲手感
- 主機管理者可能是任何同事 → 開主機與後台要讓不懂程式的人也能操作；埠被占用時自動換埠（SYS-053，未實作）
- Google Fonts 連不到用系統字型可接受；單人存檔只在瀏覽器可接受
- 缺自動化測試的需求記入 `02` R2，之後補（登入與存檔優先）
- Chrome／Edge（測試）與 Prettier（排版）寫成開發環境限制，不給 IF
- RPO 世界與玩家資料都是 1 分鐘、RTO 重開後 1 分鐘；同時在線 6 人、延遲 200 毫秒、60 FPS（可維護性優先）；效能沒實測（R3）
- 觸控降為 Should（SYS-115），不保證任何行動裝置；鍵鼠維持 Must（SYS-114）
- 重開主機：資源與怪物重生可以接受；進行中王戰消失是缺陷（SYS-035）
- 還原備份：目標是先踢出所有人、只還原該世界（SYS-042）
- 世界存檔兩份都讀不懂：目標是拒絕啟動並警示（SYS-034）
- 重設 PIN、刪除帳號的後果：寫成現況、記風險 R11
- 存檔帶 BOM 讀不懂：不改程式，README 提醒存成不帶 BOM 的 UTF-8（IF-003、R16）
- 後台 API：POST 錯誤一律 400、非冪等操作靠 admin.html 二次確認、刪除封存世界不刪玩家檔，都維持現況（IF-002）
