# ADR-0005：存檔用 JSON 檔、原子寫入、.bak 與每日備份

- 狀態：已接受（2026-11-20 追認現況）
- 日期：2026-11-20（實作於 `7d197fd`、`4810844`）
- 決策者：開發者
- 對應需求：SYS-030～042、QS-010～013、CON-001

## 背景
多人存檔放在主機上，要能撐過當機、能救回、主機管理者也看得懂。

## 考慮過的選項
1. **嵌入式資料庫**（例如 SQLite，小型遊戲伺服器常見）。
   - 切換代價：要 npm 套件或 Node 內建的 `node:sqlite`；存檔格式改成資料表，既有 JSON 存檔要寫匯入；主機管理者不能再用記事本看、改。
2. **JSON 檔**：先寫暫存檔再改名、覆蓋前保留 `.bak`、每次都從檔案讀（不快取）、每日備份保留 7 份。
3. （其他平台）**伺服器型資料庫或雲端儲存**（例如 PostgreSQL、Firebase）。
   - 切換代價：要另外安裝或連網路，違反 CON-001、CON-009、CON-012。

## 決策
選項 2。

## 理由
- 用不到資料庫：規模只有一個世界檔、一個帳號檔、每人一個玩家檔，沒有查詢需求。
- 主機管理者可以用記事本看、改；不快取，所以離線時改檔會生效。
- 不需要任何套件（CON-001）。

## 後果
- 好處：寫到一半當機也不會壞檔；備份就是複製資料夾。
- 代價：每 8 秒寫一次完整世界檔；沒有交易，世界檔與玩家檔可能有幾秒的不一致（物品重複或消失的機會很小）；兩份都壞掉時現況會默默開新世界（SYS-034）。
- 之後要注意：存檔格式改變時，遵守 CON-013（只保證已存在的相容）。

## 重新檢視的條件
- 世界檔寫入時間明顯影響 server 模擬（QS-032），而把間隔放寬到 1 分鐘仍不夠。
- 需要跨世界或跨玩家的查詢（例如排行榜）。
- 世界檔與玩家檔不一致造成的物品重複或消失被玩家回報。
