# ADR-0006：名字＋PIN＋記住登入 token，走明文 http

- 狀態：已接受（2026-11-20 追認現況）
- 日期：2026-11-20（實作於 `7d197fd`）
- 決策者：開發者
- 對應需求：SYS-020～024、QS-021、QS-040、QS-043、CON-009

## 背景
多人存檔改放在主機後，要防止別人用你的名字拿走背包；但新玩家加入要越簡單越好，而且只在區網、不做 HTTPS。

## 考慮過的選項
1. **不驗證**：只看名字。
   - 切換代價：拿掉 PIN 很容易；但任何人都能拿走別人的背包。
2. **名字＋PIN**：4～8 位數字，scrypt 加鹽雜湊；成功後發 token，瀏覽器記住，伺服器只存 sha256；錯 5 次鎖 60 秒。
3. **帳號密碼＋HTTPS**（一般網站的做法）。
   - 切換代價：要憑證（區網自簽憑證會讓瀏覽器跳警告，不懂程式的同事很難處理）；登入流程變複雜。
4. **接公司帳號**（例如 Azure AD／Google Workspace 的 OAuth）。
   - 切換代價：要公司 IT 核准與設定、要能連網際網路，違反 CON-009、CON-012。

## 決策
選項 2。

## 理由
- 範圍只到「防冒用名字」（`01` 1.2）；HTTPS 在範圍外。
- 新玩家只要輸入名字與 PIN（QS-021）。
- 即使 `accounts.json` 外流，也看不出 PIN（QS-043）。

## 後果
- 好處：簡單；同一台電腦之後免輸入；有效 token 不受鎖定，別人亂猜鎖不到本人。
- 代價：明文 http，PIN 可能被同網路的人看到（R7）；4～8 位數字 PIN 的強度有限，只靠鎖定，而且鎖定紀錄重開就清掉；重設 PIN 與刪除帳號後存檔可能被別人拿走（R11）。
- 之後要注意：README 要持續提醒不要用真實密碼。

## 重新檢視的條件
- 改成網際網路連線，或玩家範圍超出同事。
- 發生名字被冒用、背包被拿走的事件。
- 公司 IT／資安對明文傳輸有明確要求（待確認問題 #1）。
