# ADR-0001：世界由 server 用 vm 執行同一份遊戲程式模擬

- 狀態：已接受（2026-11-20 追認現況）
- 日期：2026-11-20（決策實作於 `1ed1807`）
- 決策者：開發者
- 對應需求：SYS-010、SYS-013、QS-001、QS-012、QS-032、CON-001、CON-003

## 背景
多人模式需要一個權威的世界：怪物、資源、王、日夜、熔爐都只能有一份。舊版由主機那台電腦的瀏覽器分頁擔任主機。

## 考慮過的選項
1. **瀏覽器分頁當主機**（舊版）：server 只轉發與存檔。
   - 切換代價：就是舊版，回去要恢復分頁主機的邏輯；世界又會綁在一個分頁上。
2. **server 另寫一份世界邏輯**：用 Node 重寫模擬，跟遊戲網頁分開維護。
   - 切換代價：所有玩法（怪物 AI、王、熔爐、掉落）要重寫一份並長期同步維護兩份；工作量最大。
3. **server 用 `vm` 執行同一份遊戲程式**：DOM、畫布換成替身，`MODE='host'`，30 Hz。
4. （業界常見）**專用遊戲伺服器框架**（例如 Colyseus、Nakama），或用 Go／C# 寫的權威伺服器。
   - 切換代價：要 npm 或另一個執行環境，違反 CON-001；玩法要改寫成框架的狀態模型；學習曲線高。

## 決策
選項 3。

## 理由
- 選項 1：分頁一關或切到背景被瀏覽器降頻，世界就停或變慢；主機管理者也不能把那個分頁當一般玩家用。
- 選項 2 的玩法要寫兩份，違反可維護性第 1 名（QS-001）。
- 選項 4 違反 CON-001，規模（6 人）也用不到。
- 選項 3 讓單人、玩家端、主機共用同一份玩法程式，也不需要任何 npm 套件（CON-001）。

## 後果
- 好處：沒有人在線時世界照常運作；玩法只寫一次；主機分頁可以隨時關。
- 代價：遊戲程式在載入時用到的瀏覽器 API 都要在 `startSim` 準備替身（R5）；server 端錯誤只印在主控台（R6）。
- 之後要注意：新增頂層瀏覽器 API 時，要同步補替身；測試 `00-sim-boot` 要通過。

## 重新檢視的條件
- 6 人同時在線或王戰時，server 模擬頻率持續低於 QS-032 的下限。
- 遊戲程式改成 ES module 或需要建置（會影響 ADR-0004）。
- 一個月內不只一次因為缺替身而讓多人模式起不來（R5）。
