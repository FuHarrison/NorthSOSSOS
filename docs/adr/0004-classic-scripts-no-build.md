# ADR-0004：遊戲是非模組的 classic script，不需建置

- 狀態：已接受（2026-11-20 追認現況）
- 日期：2026-11-20（拆檔實作於 `e3bcc7b`；發佈腳本 `b68dc89`）
- 決策者：開發者
- 對應需求：CON-003、SYS-001、SYS-010、QS-006

## 背景
遊戲原本是一個超過兩千行的 HTML 檔。要拆檔好維護，但仍要能用 `file://` 直接打開，server 也要能直接執行同一份程式。

## 考慮過的選項
1. **維持單一 HTML 檔**。
   - 切換代價：只要用 `tools/build.mjs` 的輸出取代原始碼；但檔案越來越大、難改、衝突多。
2. **ES module＋打包工具**（前端主流，例如 Vite、esbuild，或改用 TypeScript）。
   - 切換代價：每個檔案改成 `import`／`export`，釐清全部共用變數；要有建置步驟才能玩；server 要改成載入打包後的檔案；需要 npm。大約數天，之後很難退回零建置。
3. **依序載入的 classic script，共用一個全域範圍**；發佈時 `tools/build.mjs` 內嵌回單一檔。

## 決策
選項 3。

## 理由
- ES module 用 `file://` 打開會被瀏覽器擋掉（跨來源限制），單人模式就不能直接開。
- 不需要建置就能執行，也不需要 npm（CON-001）。
- server 讀 HTML 的 `<script>` 清單，依序在同一個 `vm` 範圍執行（ADR-0001）。

## 後果
- 好處：零建置；單人、多人、server 都用同一份檔案；發佈仍是單一檔。
- 代價：沒有模組邊界，名稱衝突與載入順序錯誤只有執行時才發現（R4）。
- 之後要注意：載入時就執行的程式只能用前面檔案的定義；載入順序唯一來源是 `北境求生.html`。

## 重新檢視的條件
- 因為全域名稱衝突或載入順序造成的錯誤，一個月內不只一次。
- 單一 js 檔超過 `<待確認：可接受的檔案行數上限>` 行而難以再拆。
- 放棄 `file://` 單人模式。
