## 1. 簡介

### 1.1 目的

北境求生是一款在瀏覽器裡玩的俯視角 2D 生存建造遊戲，屬於個人業餘專案，不是商業產品。它同時服務四個目的：

1. **同事休閒與交流**：給同事（2～6 人）在午休、下班後一起玩，不用安裝、不用花錢。
2. **自己想玩的遊戲**：做一款符合開發者口味的生存遊戲。
3. **練習技術與 AI 協作**：練習遊戲開發、多人網路同步，以及跟 Claude 協作開發的流程。
4. **練習寫規格**：這份規格本身也是練習 sys-spec 流程的範例。

本文件描述**現況（as-is）**，以 `main` 的 `3147b48` 為準。想要但還沒做的需求會標成「**未實作**」，不會寫得像已經存在。玩法細節與數值不在本文件，請見 `docs/遊戲設計企劃.md`。

### 1.2 範圍

**範圍內**
- 單人模式：直接打開 HTML 檔就能玩，存檔放在瀏覽器。
- 區網多人模式：一台電腦跑主機（server 自己模擬世界），同事用瀏覽器加入。
- 帳號：名字＋PIN，用來防止別人冒用名字。
- 多人存檔、每日備份與還原。
- 後台管理頁：只限主機那台電腦，用來管理世界、帳號與世界數值。
- 遊戲玩法：採集、製作、建造、戰鬥、寵物、王戰、地圖與迷霧等，細節見企劃。
- 基本防作弊：主機驗證玩家意圖、只接受主機發出的世界變更（**未實作**，見第 4 章）。
- 開發支援：自動化測試、排版、發佈腳本（寫成品質情境與限制條件，見 4.3）。

**範圍外**

| 項目 | 說明 |
|---|---|
| 網際網路連線 | 只支援同一個區網；不做對外開放、NAT 穿透、HTTPS |
| 舊存檔搬移保證 | 現有的相容程式維持不動（見 CON-013）；之後的新版本可以要求開新世界，不寫新的搬移 |
| 原生 App 與商店上架 | 只做瀏覽器版；觸控是在瀏覽器內支援 |
| 傳輸加密 | 接受明文 http；PIN 可能被同網路的人看到，由玩家自己不要用真實密碼 |

### 1.3 成功指標

| 指標 | 衡量方式 |
|---|---|
| 開發順利 | `docs/遊戲設計企劃.md` 第 10.2 節的路線圖項目逐項完成 |
| 品質維持 | 每次 commit 前 `node tests/run.mjs` 全部通過 |

不以玩家人數或遊玩時間衡量。

### 1.4 名詞定義

| 名詞 | 定義 |
|---|---|
| 主機（server） | 執行 `server.js` 的那台電腦與程式；提供網頁、轉發訊息、存檔，並自己模擬世界 |
| 世界模擬（sim） | server 用 Node `vm` 執行同一份遊戲程式，`MODE='host'`，不畫畫面 |
| 玩家端（client） | 多人模式下的每個瀏覽器分頁，只模擬自己的角色與寵物 |
| 單人模式（solo） | 用 `file://` 打開，或連不上 WebSocket 時；所有東西在瀏覽器內跑 |
| 主機管理者 | 開主機、用後台管理世界與帳號的人；可能是任何同事，不一定懂程式 |
| 後台 | `admin.html`，網址 `/admin`，只限主機那台電腦打開 |
| 世界數值（CFG） | 每個世界各自的難度、掉落、一天長度、死亡懲罰、免費建造等設定，存在 `world.json` 的 `cfg` |
| 意圖（act） | 玩家想做的動作，送給主機處理 |
| 世界變更（evt） | 主機決定的世界狀態改變，廣播給所有玩家 |
| 在線玩家 | 目前有 WebSocket 連線、已登入的玩家 |

## 3. 系統情境
系統由兩個部分組成：**遊戲網頁**（`北境求生.html`＋`css/`＋`js/`）與**主機程式**（`server.js`＋`admin.html`）。單人模式只用到遊戲網頁。情境圖見 `02` 第 3 章。

| 對象 | 方向 | 互動內容 | 介面 |
|---|---|---|---|
| 玩家（瀏覽器） | 雙向 | 取得遊戲網頁；登入；送出玩家意圖與自身狀態；收到世界快照、世界變更、私人訊息 | IF-001 |
| 主機管理者（主機那台電腦的瀏覽器） | 雙向 | 查看狀態；管理世界存檔、備份、帳號；下達世界即時指令與世界數值 | IF-002 |
| 主機管理者（黑色視窗） | 單向（人 → 系統） | 雙擊 `開主機.bat` 啟動；關閉視窗停止（先存世界）；看主控台訊息與同事網址 | 無（本機操作） |
| 檔案系統 `saves/` | 雙向 | 世界、帳號、玩家存檔、封存世界、備份 | IF-003 |
| Google Fonts | 單向（瀏覽器 → 對方） | 下載標題字型 Noto Serif TC | IF-004 |
| 瀏覽器 localStorage | 雙向 | 單人存檔、個人設定、登入 token、名字 | 瀏覽器內建，不另立 IF |

## 5. 品質屬性需求

品質需求以品質情境（QS）表達，每個 QS 直接寫出來源 STK；「對應 SYS」是它約束的功能需求，可以空白（見 `docs/README.md`）。

### 5.1 優先順序

| 名次 | 屬性 | 理由 |
|---|---|---|
| 1 | 可維護性 | 業餘專案、跟 AI 協作，功能持續增加；最大的風險是改壞多人同步或 server 端模擬 |
| 2 | 可復原性 | 長期世界的進度最珍貴；壞了要救得回來 |
| 3 | 易用性 | 主機管理者可能是任何同事，不一定懂程式 |
| 4 | 效能 | 多人一起玩不能卡 |
| 5 | 安全 | 防冒用名字、後台不被別人操作、基本防作弊 |

不列入前幾名：可用性、可稽核性、可觀測性、擴展性、成本。

### 5.3 屬性之間的取捨
| 衝突 | 決定 |
|---|---|
| 60 FPS（效能）vs 可維護性 | **可維護性優先**。60 FPS 是目標；王戰等尖峰時可以低於 60，下限 `<待確認：尖峰時可接受的最低 FPS>`。不為了 FPS 做會讓繪圖程式難改的最佳化。 |
| 防作弊（安全）vs 延遲、可維護性 | SYS-080、081、082 維持 **Should**；之後實作時**不能犧牲手感**：自己的動作仍要按了立刻反應，看到世界變化仍在 200 毫秒內（例如本機先扣、主機事後驗證）。 |
| 可復原性 vs 效能 | 目前每 8 秒寫一次完整存檔，比 SYS-030 的 1 分鐘更嚴格；如果寫檔影響效能，可以把間隔放寬到 1 分鐘以內，仍符合 SYS-030。 |

## 6. 限制條件

| 編號 | 類別 | 限制 | 理由／來源 |
|---|---|---|---|
| CON-001 | 技術（硬性） | 執行時零外部依賴：`server.js`、`admin.html`、遊戲網頁只用 Node 22+ 內建模組與瀏覽器內建 API，不需要 `npm install`。例外：標題字型從 Google Fonts 下載，連不到時改用系統字型（IF-004、ASM-003） | 主機管理者可能是不懂程式的同事（STK-010、STK-023、QS-020） |

| CON-005 | 技術 | 玩家端支援**桌機版 Chrome／Edge 最新版**；其他瀏覽器與行動裝置不保證（觸控見 SYS-115） | 公司電腦常見；測試也用這兩個瀏覽器跑 |

## 8. 資料需求

| 資料 | Source of Truth（現況） | 本系統讀／寫 | 保存與備份 | 備註 |
|---|---|---|---|---|
| 多人世界：**會存檔的部分**（seed、地圖大小、天數與時刻、王的召喚與擊敗旗標、建築與箱子／熔爐／作物內容、地上袋子、共享迷霧、世界數值 `cfg`） | server 的世界模擬（記憶體） | sim 讀寫；寫入 `saves/world.json` | 每 8 秒自動存；`.bak` 一份；每日備份最近 7 份；切換／開新世界時舊世界封存成 `world-<時間>.json` | 地形由 `seed` 決定，玩家端自己重新生成 |
| 多人世界：**不存檔的部分**（資源的採集狀態、怪物、進行中的王戰） | server 的世界模擬（記憶體） | sim 讀寫，不寫檔 | 無；主機重開後資源與怪物依 seed 重新生成（接受），進行中的王戰消失（缺陷，SYS-035） | |
| 多人玩家個人資料（背包、快捷欄、寵物、個人迷霧） | **玩家自己的瀏覽器** | 瀏覽器用 `psave` 送整份，server 只代存到 `saves/players/<seed>-<名字>.json`；登入時回傳 | `.bak` 一份；每日備份 | 目標是改成主機為準（**未實作**，SYS-081）；這也是 STK-005 未達成的根本原因之一（另一個是 SYS-082） |
| 帳號（PIN 的加鹽 scrypt 雜湊、最多 5 個記住登入 token 的 sha256 雜湊） | server | server 讀寫 `saves/accounts.json` | `.bak` 一份；每日備份；還原備份時**不還原帳號** | |
| 單人存檔 | 瀏覽器 localStorage `northland-save-v1` | 遊戲網頁讀寫 | 無備份；清除瀏覽器資料就消失，不能搬到別台電腦（接受，ASM-002） | 格式維持向後相容（SYS-002） |
| 個人設定（音量、黑白濾鏡等）、名字、登入 token | 各台電腦的瀏覽器 localStorage | 遊戲網頁讀寫 | 無 | 每台電腦各自一份 |
